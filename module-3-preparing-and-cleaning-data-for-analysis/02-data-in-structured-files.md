# 3.2 Data in Structured Files

---

## 3.2.1 What is structured data?

**Structured data** is data that lives in **defined fields** inside a file or record. Because everything has its own spot, a computer can easily enter it, sort it, search it, and analyze it.

You've made structured data before without thinking about it. When you fill out a website form with your name, address, and billing info, that's structured data. The form (and the database behind it) often *forces* you to type things in a certain way so the computer can understand them.

You'll find structured data in things like **relational databases** and **spreadsheets**.

### What makes data "structured"?

- It has a clear, organized structure
- It's usually stored in **tables**, with vertical **columns** and horizontal **rows**
- The content and format are **documented** (someone wrote down what goes where)
- It's organized into **files, records, and fields**
- It can be **searched, sorted, and queried**
- **Input controls** cut down on invalid data (like a form that won't accept letters in a phone number field)

That last one is a big deal. If the data goes in clean, there's less cleaning to do later.

---

## 3.2.3 CSV files

Different apps save data in different formats, and those formats don't always work together. So we need something universal.

**CSV (Comma-Separated Values)** is a plain text file format that's used everywhere to standardize data.

How it works:

- **Columns** are separated by commas (or sometimes tabs, spaces, or colons)
- **Rows** are separated by a newline character (basically hitting Enter)
- Each row can also be called a **record**

Here's a quick example I made up to show the idea:

```
name,age,city
Alex,20,Paris
Sam,22,Toronto
Priya,21,Sydney
```

The first line holds the column names. Every line after that is one record. Open it in a spreadsheet and it turns into a neat table.

CSV files are commonly used to **import and export** data to spreadsheets and traditional databases. They can also be fed into analytic programs and visualization tools.

### JSON and XML

Two other standard plain text formats you'll see a lot:

| Format | What it is |
|---|---|
| **JSON** (JavaScript Object Notation) | A lightweight data format that's easy for humans to read and write |
| **XML** (Extensible Markup Language) | A markup language similar to HTML |

Both work with tons of different applications. And here's the useful part: **converting data into a common format is a great way to combine data from different sources.**

## 3.2.5 Types of structured files

Structured data files can be made by humans or generated by machines. Here are the main ones:

### 1. Relational databases

A collection of **tables** (columns and rows) connected by **pre-defined relationships**.

- Each table holds info about one kind of object
- Each **column** holds one kind of data
- Each **field** in that column stores the actual value of an attribute

### 2. Logs

A machine-generated **history of everything that happens** in a system, like transactions, errors, or intrusions.

Logs count as structured data because machines create them, so they follow a standard format.

### 3. Spreadsheets

A spreadsheet is an example of a **flat file database**.

- A flat file database stores records in **one single file** with **no hierarchical structure**
- Like database tables, data is in rows and columns, with related items lined up either horizontally or vertically

### 4. Sensor readings

Sensors (think temperature or motion sensors) usually output data in a **standardized format**, though it can differ by manufacturer.

- Readings might be separated only by a **delimiter**
- Or they can be **time dependent**, like 1 reading per second, separated by **timestamps**

### 5. Transactional records

Records of transactions can be stored in lots of different formats, depending on the type of transaction and where it came from.

- Some are entered **manually** into forms
- Others are **machine-generated**

### Quick comparison

| File type | Made by | Key idea |
|---|---|---|
| Relational database | Humans and systems | Tables connected by relationships |
| Logs | Machines | History of system events in a standard format |
| Spreadsheets | Humans | Flat file, one file, no hierarchy |
| Sensor readings | Machines | Standard format, often with timestamps |
| Transactional records | Both | Format depends on transaction type and source |

---

## Quick takeaways for this part

- **Structured data** sits in defined fields, so computers can easily search, sort, and analyze it.
- It's organized into **files, records, and fields**, usually as tables.
- **Input controls** help stop invalid data from getting in.
- **CSV** is a universal plain text format: commas split columns, newlines split rows.
- **JSON** and **XML** are other common standard formats, great for combining data from different sources.
- Common structured file types: relational databases, logs, spreadsheets, sensor readings, and transactional records.
- A spreadsheet is a **flat file database**: one file, no hierarchy.
